# v1.0.0: the review's findings

**Status:** task 1 of [v1.0.0.md](v1.0.0.md), done on `dev-v1.0.0`; the owner chooses what is fixed (task 2).

Each finding has a number, what was found, why it matters, and a proposed fix. **Weight:** *fix* is a real fault; *should* is worth doing for 1.0; *nit* is small.

## How it was reviewed

- **Code quality:** every module was read for dead code, duplication, unused exports and stale comments. The checker runs strictly (`strict`, `noUnusedLocals`, `noUnusedParameters`) and passes; there are no `TODO`, `FIXME` or `console.log` left.
- **Tests:**
  - line, branch and function coverage of `pnpm test`, by Node's own coverage (`--experimental-test-coverage`);
  - which page code only the browser checks reach.
- **Docs:** every path named in the docs and comments checked against the files; the developer docs read against the code; wording about features that changed (the Start tab, the cassette recorder, the joystick, the languages) searched for everywhere.

## Code quality

**C1 (fix). Some buttons lose their names on a phone.**
- The helper strip's buttons (Computer, Ctrl-Reset, TV, the drive) hide their words in a narrow window (`.strip-label { display: none }`). Their tip goes to `aria-description`, not `aria-label`, so a screen reader hears no name at all.
- The lesson bar has the same problem when it is compact: its other tabs show only their numbers.
- The dock's tabs and Programs are already handled (`js/app/main.js`, "a button whose words a narrow window hides keeps them as its name").
- *Fix:* give these buttons their words as `aria-label`, kept up to date when the drive's label changes. Folds into task 7.

**C2 (nit). The same file-name cleaning, twice.** `js/app/topbar.js` cleans a file name with the same regular expression in `programName` and in `saveAs`. *Fix:* one helper.

**C3 (nit). Exports nothing else uses.**
- About 25 names are exported but used only in their own file.
- Some are deliberate: named constants of the machine (`LINE_CYCLES`, `TRACKS`, `OPS`).
- Some are pure helpers that ought to be tested (T3): `programName`, `decodeText`, `markup`, `rich`, `parseHex`.
- The rest could simply stop being exported: `closeMenu`, `ribbonTextures`, `polylineLength`, `freeShape`, `silhouette`, `showCode`, `VIEWS`, `SPEEDS`, `TOOLS`, `LIFT`, `LIFT_PART`, `OUT_S`, `BACK_S`, `BAKE_PX_MM`.
- *Fix:* test the helpers, keep the machine's constants, and unexport the rest.

Nothing else was found: no dead modules, no leftovers of the joystick or the Start tab in the code, and the comments agree with the code.

## Tests

**T1 (should). The machine's code is well covered, with a few gaps.**
- `pnpm test` (217 tests) covers 98% of the lines and 91% of the branches of `js/sim`, the lessons, the programs and the messages.
- **The game port is never read in a test** (`js/sim/machine.js`, the paddles and buttons). Games from disks read it: Mario Bros polls button 0 about 23 times a second. A test should pin "nothing plugged in": paddles at 255, buttons up.
- **`js/sim/sound.js` is at 58%.** Its player is browser-only, but the click-to-wave arithmetic could be tested in Node.
- **`js/sim/system.js`:** a few error branches (a refused disk, LOGO not running when asked) are never taken.

*Fix:* tests for these three.

**T2 (should). The page's own code has no coverage figure.**
- `js/app`, `js/ui`, `js/scene` and `js/flat` are about 6,000 lines. They are reached only by the browser checks (115), which nothing measures.
- *Fix:* `pnpm test:browser --coverage` collects V8's precise coverage through the Chrome DevTools Protocol, which the harness already speaks, and reports it per file. Then fill the gaps it shows.

**T3 (should). Pure helpers in page files have no unit tests.**
- `programName` and `decodeText` (`js/app/topbar.js`), `markup` (`js/app/lessons.js`), `rich` (`js/app/references.js`), `parseHex` (`js/app/tools/cpu.js`), and the write side of `js/app/link.js`.
- They need no DOM.
- *Fix:* unit tests.

**T4 (should). The browser checks are not in CI.**
- They are run by hand before a release, so a fault in the page can sit on a branch unnoticed.
- GitHub's Ubuntu runners have Chrome.
- *Fix:* a second CI job running `pnpm test:browser`, about five minutes, beside the unit tests.

**T5 (should).** The full 6502 suite has not run since v0.0.2. It is already task 10.

## Docs

It says they take "a few minutes" and are "not in CI"; that changes with T4. *Fix:* rewrite the paragraph from `tests/browser/run.mjs`'s list.

**D2 (fix). The code map in the conventions misses folders.**
- `docs/conventions.md`'s table of where code goes has no `js/lessons/`, no `js/programs/` and no `js/app/tools/`.
- It says `js/sim/` holds "the speaker" but not the disk drive.
- *Fix:* bring the table up to date.

**D3 (nit). Three paths in docs and comments lead nowhere.**
- `model/README.md` names `tools/make_board.py` and two siblings, which live in `model/tools/`. Relative to the README they are right, but they read wrong from the root.
- `docs/licensing.md` and `tools/harte6502.mjs` name `tests/data/harte6502-sample.js`; the file is `.json`.
- *Fix:* name them as they are.

**D4 (none).** The design notes of v0.0.1–v0.0.5 keep their history (the Start tab, the cassette plans) on purpose. Everything current agrees: the README, the roadmap, the decisions, the UI design, the page's own words.

**D5.** The READMEs are rewritten in task 3. The link format is already documented (`docs/ui-design.md`, P8) and pinned by `tests/link.test.js`; task 5 adds the developer options and the save formats.
