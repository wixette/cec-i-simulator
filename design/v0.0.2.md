# v0.0.2: instruments that show how it works

**Status:** built on branch `dev-v0.0.2`, waiting for the owner's check.

v0.0.2 adds the instruments: views the real CEC-I never had, read off the running machine, each in a tab of the dock beside the machine (docs/ui-design.md, U12). They show how a computer of 1987 works, and how this one shows Chinese, which no other computer of its class could.

Related documents: the page's principles and decisions ([../docs/ui-design.md](../docs/ui-design.md)), the machine's decisions ([decisions.md](decisions.md)), what the machine is ([../research/README.md](../research/README.md)).

## 1. What a visitor can do

- **CPU & Memory:** see the 6502's registers and flags, and the next instructions disassembled, as the Apple II monitor would list them. Pause the machine, step it an instruction at a time, run it to an address, or run it 10, 100 or 1,000 times slower; everything waits while it is paused (the picture, the keys, typing). See the memory map lit by where the 6502 reads and writes, and a memory dump that follows PC, the stack or an address.
- **Screen:** see the display's soft switches and what they make the picture show; the text (or lo-res) page as its 40 × 24 bytes, live, at their interleaved addresses; pick a byte to see it become a character from the character ROM U13, or two lo-res blocks; and see one hi-res line: its address worked out, its 40 bytes as dots, bit 7's half-dot shift marked.
- **Chinese:** follow a character from the string to the screen: a string variable's bytes, each 127 x y a character; the latch at $C0B0 and which 16 KB of the 256 KB font its window shows; the 32 bytes of the last character read through it, as 16 × 16 dots, its glyph number and where it is in the font; and where its dots are on the hi-res page.
- **Keyboard:** see the key matrix, each key at the crossing of an X line and a Y line, lit while down; the last key's code worked out in the keyboard ROM U26 (its group 10 X + Y, its address, its byte); and the latch the program reads at $C000, with its strobe.
- **Inside:** the chips light as they work: the 6502 while it runs, the RAM, the system ROM U7, the Chinese ROM U35, the font ROMs U33 and U34, the latch U32 as it is written, the character ROM U13 while text is shown.

## 2. How it is built

| Part | Where | Notes |
|---|---|---|
| The disassembler | `js/sim/disasm.js` | The CPU's own opcode table (`cpu6502.js`, opInfo), so they cannot disagree; the monitor's notation |
| Reading without side effects | `Machine.peek` | The instruments read memory as the CPU would, without clearing the keyboard's strobe or flipping a switch |
| The memory traffic | `Machine.takeTraffic` | Reads and writes counted by 256-byte page of RAM and by chip; the map's regions (`js/sim/memmap.js`) and Inside's chips sum them |
| The clock | `System.pause`, `step`, `runTo`, `setSpeed` | Run to stops before the instruction at the address; the slower clock carries fractions of a cycle |
| The Chinese path | `js/sim/glyphs.js` | Ported, with review, from the work the machine was built on: a watch on the latch and the font window (`Machine.watch`), the string variables, the glyphs found on the hi-res page |
| The key lookup | `Keyboard.lookup` | U26's address for each key and its modifiers; the last one kept |
| The tools | `js/app/tools/` | `cpu.js` after the TRS-80 simulator's, `screen.js`, `hanzi.js`, `keyboard.js` |

## 3. Checks

- Unit tests: the disassembler (each mode, branches, the ROM's own code), the clock (pause, step, run to, slower), the traffic, `peek`, the U26 lookup, and the Chinese path on the running machine: 中华学习机 is 15 bytes; printing 中 writes bank 9 to $C0B0 with colour off; 中 is glyph 4721, read whole through the window as the font ROMs hold it; its dots found on hi-res page 2 at a 16-dot column, over 48 bytes.
- Browser checks: each tab opens and shows the running machine; Pause, Step and Run to; a key pressed lights the matrix and shows its U26 lookup; Chinese printed shows in the Chinese tool; Inside lights the 6502.
